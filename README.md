# RED OS Package Updater

Утилита с графическим интерфейсом для массового обновления серверов RED OS по SSH: заходит под root, ставит обновления (ядро kernel-lt + security или только security), корректно гасит критичные сервисы, при необходимости перезагружает и делает пост-проверку. Всё в одном exe.

## Что нужно на машине сборки

- Windows с .NET Framework 4.6.2+ (нужен `csc.exe`, он идёт вместе с фреймворком).
- Папка `libs\` с `Renci.SshNet.dll` и зависимостями (уже собраны в проекте).

## Сборка

Из корня проекта (там, где лежат `src\`, `profiles\`, `libs\`, `build.cmd`):

    build.cmd            - пустой exe (для любого заказчика)
    build.cmd seed       - exe с предзаполнением из seed\seed_config.json

На выходе `RedOSPackageUpdater.exe`. К заказчику переносится **только этот файл** — SSH-движок, зависимости и bash-профили вшиты внутрь.

Требование к машине заказчика: установленный .NET Framework 4.6.2+ (на Windows Server 2008 R2 SP1 ставится).

## Обновление программы

При запуске программа анонимно проверяет публичный репозиторий GitHub. Новый EXE скачивается,
когда версия в `update.json` выше установленной либо SHA-256 опубликованной сборки отличается при
том же номере версии. После загрузки SHA-256 проверяется повторно. Ручная проверка:
`Дополнительно → О программе → Проверить обновления`.

Новый релиз собирается одной командой из PowerShell:

```powershell
.\release.ps1 -Version 1.2.0 -Notes "Краткое описание релиза"
```

Скрипт синхронизирует версию исходников, собирает EXE и записывает его SHA-256 в `update.json`.

## Хранение

Всё в `%LOCALAPPDATA%\RedOSPackageUpdater`:

- `config.json` - системы, узлы, пул учёток (пароли зашифрованы DPAPI на текущего пользователя Windows).
- `creds_cache.dat` - кеш подобранных учёток по узлам (DPAPI).
- `known_hosts.json` - подтверждённые SHA-256 отпечатки SSH-ключей серверов.
- `vulndb\` - локальный компактный каталог БДУ ФСТЭК.
- `logs\run_<дата>\` - подробные логи по каждому узлу + `summary.csv`.

Предзаполнение (`seed`) применяется один раз при первом запуске, дальше всё редактируется через интерфейс и живёт в `config.json`. Вшитые узлы можно свободно менять и удалять.

## Учётки (пул + подбор + кеш)

Пароли не привязаны к узлам. Есть общий пул учёток (по умолчанию логин `root`). Для каждого узла программа сначала пробует закешированную рабочую учётку, если не подошла - перебирает пул, найденную кеширует, старую убирает. Если сменили пароль - на следующем прогоне произойдёт новый подбор.

Пароли и IP можно вводить массово через копипаст (кнопки «Массово узлы» и «Массовый ввод паролей»).

Внимание: перебор паролей может ловить блокировки (fail2ban / pam_faillock). В настройках есть пауза между попытками и лимит попыток.

## Экспорт / импорт

`Файл → Экспорт/Импорт` - переносит системы, узлы и пул учёток между машинами. Файл шифруется
мастер-паролем (PBKDF2, AES-256-CBC и HMAC-SHA256), потому что DPAPI на другой машине не расшифруется.

## Профили обновления

- **Ядро kernel-lt + security** - обновляет `kernel-lt`, ставит security-обновления (PostgreSQL исключён намеренно), выставляет default-ядро, чистит битые записи GRUB/BLS. Требует reboot.
- **Только security** - ставит только security-обновления, ядро не трогает. Reboot только если реально нужен.

Перед обновлением на хосте делается бэкап в `/root/rpu-backup-<дата>`: список пакетов (`rpm -qa`), текущее ядро, `dnf.conf`, `/etc/sysconfig/kernel`, точка `dnf history`. Откат security-обновлений: `dnf history undo <id>`. Старые бэкапы ротируются (хранится последние N, настраивается).

Профили явно поддерживают RED OS 7.3 и 8.0. Неизвестная версия ОС блокируется до изменения узла. На RED OS 8 используется только DNF; RPM release `.red80`, UEFI/BLS и `dnf needs-restarting` обрабатываются без установки дополнительных пакетов.

Reboot делается только если он реально нужен (проверка через `needs-restarting`), и только после корректной остановки критичных сервисов. Список сервисов задаётся на подсистему (маски вроде `postgresql*`, `patroni`, `pgbouncer`) - имя PostgreSQL не хардкодится, маски разворачиваются в реальные systemd-юниты. Если сервис не остановился в таймаут - reboot этого узла отменяется.

## Запуск

Отметить узлы галочками и «Запустить отмеченные», либо правый клик по системе/узлу - «Запустить систему» / «Запустить этот узел». Работа идёт параллельно (число потоков в настройках). Справа - живой лог и сводная таблица со статусами (двойной клик по строке открывает полный лог узла).

Галочка «Не перезагружать» - только подготовка (обновление и проверки), без reboot.

## Проверка уязвимостей БДУ ФСТЭК

Проверка состоит из трёх уровней доказательности:

- основной уровень: `dnf updateinfo --security` на узле возвращает реально доступные исправления производителя RED OS, установленные/исправленные RPM-версии и CVE; на управляющем ПК CVE связываются с БДУ ФСТЭК;
- общий продукт `Linux`: официальная XML-выгрузка БДУ ФСТЭК разбирается на управляющем ПК, после чего версия работающего ядра сопоставляется с однозначными диапазонами своей ветки (`до 6.1.174`, `от X до Y`).
- Trivy не устанавливается и его база не передаётся на узлы: штатная проверка использует security advisory RED OS.

Серверу достаточно настроенного внутреннего репозитория RED OS; прямой доступ в интернет не нужен.
Каталог БДУ хранится внутри программы и на управляющем ПК. Неоднозначные свободные
описания версий намеренно не считаются подтверждёнными. `fstec_vulnerabilities.csv` и HTML содержат
только подтверждённые vendor advisory либо однозначным диапазоном работающего ядра записи. Все исходные результаты остаются в
`all_vulnerabilities.csv` со статусом применимости и причиной исключения. Автоматическое обновление
для общего продукта Linux не предлагается без конкретного advisory RED OS.

Команда `Уязвимости ФСТЭК → Обновить базу из интернета` строит локальный каталог непосредственно из официальной XML-выгрузки БДУ без скрытого перехода на резервную копию. Для изолированного
управляющего ПК можно отдельно импортировать официальный `vulxml.zip` через команду импорта базы.

## Состав проекта

    src\           - исходники C#
    profiles\      - bash-профили (вшиваются в exe)
    libs\          - Renci.SshNet.dll и зависимости (вшиваются в exe)
    seed\          - предзаполнение (опционально, build.cmd seed)
    tools\         - воспроизводимая генерация многослойной иконки приложения
    build.cmd      - сборка одного exe
    test.cmd       - регрессионные тесты C# и проверка синтаксиса shell-профилей (если установлен Git Bash)

Крупные границы внутри `src`:

- `MainForm*` — только управление UI и запуск сценариев;
- `AppIcons`, `WindowChrome`, `ModernControls` — единая моноширинная иконографика, утверждённые оптические варианты знака, собственная строка заголовка и современные контролы;
- `SshOrchestrator` — последовательность операций над узлом;
- `SshCommandRunner` — потоковое исполнение, таймаут и отмена SSH-команды;
- `ConfigurationRules`, `ParallelBatch` — проверяемые правила конфигурации и параллельного запуска;
- `VulnerabilityDatabaseService` — обновление/импорт каталога БДУ;
- `VulnerabilityReportService`, `PreviewReport` — подготовка CSV/HTML/XLSX;
- `Store`, `Crypto` — атомарное хранение и защита секретов.
